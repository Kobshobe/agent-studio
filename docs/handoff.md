## 工作方式

1. 读契约，逐条对齐字段与错误码。**不要改契约。**
2. 写 `.changes/<slug>/` 的三层：`intent.md`、`spec.md`、`plan.md`。`plan.md` 要有 `## Files`、`## Layout`、`## Proof`。
3. 用 worktrunk 开 worktree；多端时遵守「生产端先合、消费端从合并后的主线重开」。
4. 派子 agent 时，边界和验收写进 `plan.md`，prompt 只给环境、禁令、汇报格式。
5. 收口后归档变更链，更新 [`architecture.md`](architecture.md)。

## 完成标准

```sh
make check-all
```

必须退出码 0，并且：

- 两端测试全部通过
- 端到端能跑通
- 契约没有被改动
- `.changes/` 里没有残留的进行中链

## 汇报

用中文，只讲事实：创建了哪些文件、门禁的实际输出与退出码、端到端结果、契约 sha、做的取舍、契约里你认为有歧义的地方。

## 契约有问题怎么办

不要自己改契约，也不要自行定义契约之外的行为。把问题写进 `spec.md` 的 `## Areas of concern`，记下**你选了哪个口径、为什么**。裁决权在契约维护者，不在你；本轮不因为它阻塞。

## 完成时

代码交上来不算完，还要让下一个人能接着干：

- 把本文件「## 现状」表改成收口后的样子，或写明「已完成，见归档链」。
- 把变更链归档到 `.changes/archive/`。
- 更新受影响的状态文档：`docs/layout.md`（目录或归属变了）、`docs/architecture.md`（组件或数据流变了）。
- 新增的文件级结构要登记进 `docs/layout.md`，否则下一轮只能读源码。
